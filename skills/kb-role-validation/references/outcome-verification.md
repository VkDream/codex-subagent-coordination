# 按真实入口验收最终结果

把完成声明映射为可观察结果：操作前的状态、实际入口与身份/环境、原始输入、明确完成点，以及操作后的状态/产物和必要的副作用检查。HTTP 成功、消息已接受、按钮可点和界面提示只证明各自那一层；异步接受不等于最终提交，生成文件不等于文件可读。

## 选择最小场景

围绕本次新增或受影响的流程，选择能证明完成行为的成功路径，以及能揭示已知问题或相关风险的必要失败/边界。共享规则影响多个实际入口时覆盖其行为差异；没有相关风险不展开整套矩阵，未受影响的有效证据继续复用。

先核对产物、配置与被验 revision 的关联。初始状态应能代表本项目的实际约束，确认结果由本次动作产生。夹具可以准备前置条件，但不能替代正在验证的步骤或预置它的结果：验证导入就经过原始文件导入，验证控件绑定就经实际控件触发。精简样例须保留原触发条件；更换身份、数据关系或配置后取得的结果不能直接证明原问题已修复。

## 按项目类型选入口与观察点

只使用当前任务授权的环境和层级；本方法不增加运行、数据写入、重启、真实 DLL 或硬件权限，用户指定的人工验收方式继续有效。以下按当前改动选用，不要求每个项目执行全部类型。

| 项目/入口 | 本次需要观察的结果 |
|---|---|
| Web 页面、表单、按钮 | 从实际页面操作到业务结果；保存、跨页状态或缓存受影响时刷新/重进读回。接口独测只计接口证据。 |
| WPF/MFC 等桌面界面 | 从实际窗口/控件/命令到用户可见状态、配置或文件；保存相关时重新打开读回，失败恢复相关时观察忙碌/禁用状态能否结束。 |
| API、服务、CLI、脚本 | 从实际公开入口到响应/退出码及可读输出、最终状态；异步任务观察约定完成点。按实际影响检查取消或重复请求。 |
| DLL、设备与工业控制 | 从实际消费方到调用结果、状态/快照和相关资源释放；模拟或 NoHardware 只证明已运行的对应路径，真实 DLL、硬件分别取证。 |

## 读回与失败恢复

持久化或重进相关改动，从新的读取动作核对已提交结果；测试后不以旧界面缓存代替读回。异步操作按明确完成条件作有界等待，未观察到完成不能只凭已接受信号判成功。

能观察事件或状态时，复用项目现有等待机制，等待本次动作对应的条件，每次判断读取新状态，不用固定 sleep 猜完成时间。条件未达到时保留超时与失败原因；不照搬固定轮询间隔或新增通用等待框架。测试防抖、节流或周期等时间行为时，先确认触发条件，再按已知时序等待并注明依据。

失败、取消、部分成功或忙碌状态影响后续操作时，在同一会话观察失败后修正/重试能否继续，以及等待状态、资源和已成功部分是否按合同处理。其他独立样例隔离初态，避免前例污染。重试有副作用时只在已授权且可控的对象/环境内执行；不通过清理真实数据或重启他人服务制造测试条件。

## 结论与证据

条件满足且结果正确为已通过；有决定性相反观察为失败；缺环境/权限导致无法执行为阻断；未做为未执行；观察不足以裁决为 UNKNOWN。已经看到违反合同的结果不能用 UNKNOWN 淡化；没有运行也不能用失败代替缺证据。

验证可复现缺陷的修复时，优先复用可核验的修复前失败证据，以相同输入、关键初态和同一安全/正确性断言核对修复后结果。确认两侧检查确实到达与原缺陷相关的入口、观察点和断言；与目标断言无关、使检查提前退出的依赖、编译或启动错误，不算原缺陷复现。相关合法行为是否保留另行判断，不把与安全不变量无关的错误文案或返回类型变化混作安全断言。缺少基线或无法运行时分开报告已证结论与证据缺口，不声称完成了前后运行对照；不为补证回退真实工作树、修改真实数据或越权执行。此方法不要求每次修改都新增测试或重跑未受影响的有效检查。

失败保留最小复现输入/时序、实际与期望结果及精确产物/命令来源。优先观察行为；验证角色不改源码或重新做完整源码审查。可复现产品问题按既有边界回修复，环境/权限/合同问题回总监。引用已有证据时保留其原层级，不冒充本轮独立执行；结论只覆盖实际授权并执行的范围，沿用原修正预算与停止条件。
