# 做通行为，而不只做完文件

修改前从用户入口走到真正生效的状态/输出：谁生产输入，谁决定规则，谁拥有状态，哪些真实消费者看到结果。只画脑中或合同内的短链；没有跨界问题就不建图表。已有共享能力可复用时，在正确所有者处修正；不同入口行为本来不同则不要强行统一。

把本次行为分成“应改变”与“必须保留”。重点检查容易被顺手归一化改变的语义：零与缺失、空与非法、顺序、身份、默认值、大小写、错误类型和历史数据兼容。例：给列表增加过滤不能改变明细查找规则；成功值更新不能绕过失败时保留旧值的合同。具体保留项来自当前合同和消费者，而不是固定模板扩需求。

实现完成后反向穿过直接消费者：调用是否真正进入新路径，失败是否到达可见错误，状态是否只有一个写入者，取消/清理是否仍属于原所有者。搜到符号只能定位，不能证明接通；接口、包装层或测试替身存在也不等于生产调用成立。

挑能区分正确和错误实现的行为测试：至少让已知旧行为或一个可信的局部错误在同样输入下给出不同结果。优先复用已有基线失败；必要时仅在隔离副本做负向对照，不为证明测试而回滚真实工作区。断言用户输出、最终状态、错误与副作用，而非只断言 mock 调用或源码出现某个词。

验证范围按影响切片：改变一个共享规则，就覆盖其真实入口与关键保留行为；未涉及的独立验证保持有效，不重跑。不依赖原错误的失败要先分类，不能削弱断言换绿灯。修正次数、扩大验证和停止仍按主 Skill 与合同；这些方法不产生新的预算或授权。
