# 以可达反例提高深度，以现有保护减少误报

先按合同看应完成的行为，再沿实际变更及直接调用链看正确性。候选缺陷可以用短因果链自检：可达入口/输入 → 当前分支或事件顺序 → 被破坏的不变量 → 用户影响。给出精确位置；只有“可能线程不安全”或“看着复杂”不构成修复单。

对同一候选主动找最强的反证：上游前置条件、身份/版本检查、锁的覆盖范围、错误分支、补偿、生命周期和消费者约束是否已消除触发条件？保护必须覆盖发生副作用的路径与时段；成功分支有检查不能自动保护异常、取消或清理分支。涉及时序时写一个最短事件序列，不据同步冒烟推定乱序安全。只在授权范围内复现，否则明确为静态路径证明。

测试本身也要审：断言能否在真实实现坏掉时失败，还是只验证替身、返回码、预先填好的状态？输入是否真正走到目标分支，检查是否在异步操作结束后发生，失败是否被吞掉？优先检查已有测试逻辑与记录；缺覆盖说明证据缺口，只有建立真实故障路径后才另列产品缺陷，不把“没测试”等同“功能必错”。

结论分三类，避免无意义返工：已证实且有影响的缺陷给最小修复方向；需要更高证据或关键事实的疑点标 UNKNOWN 并给最窄观察；命名/排版等非合同要求、无实质影响的偏好作为非阻断建议或省略。兼容、安全、所有权和不必要复杂度可以是实质问题，但要给当前代价/风险证据，不能借偏好豁免。

同根发现合并，保留不同受影响入口；也说明关键候选为何排除，而非输出一长串假想风险。两条审查轴和前审放行仍按主 Skill；这些方法不允许实施者自称独立通过，也不允许审查者改工程。
