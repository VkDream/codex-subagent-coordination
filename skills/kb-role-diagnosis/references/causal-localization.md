# 找到首个偏离，而非最后一个报错

先确认观察对应的对象：当前源码、构建产物、实际加载产物、配置和用户输入是否为同一实例/版本/时段。某层身份未证实，就把诊断限定在已有证据，不能从源码正确推出现场包正确；也不为确认身份默认做哈希或全盘扫描。

沿最短实际链检查“进入该边界的值/状态 → 使用的转换或选择条件 → 离开边界的值/状态”。只追与失败有关的字段，保留关联身份、顺序与必要单位，不记录凭据和无关数据。找出最后一个正确点与第一个不正确点；后续错误可能只是传播结果，不逐层各算一个根因。

有工作正常的同类样本时，比较导致不同结果的实际差异，而非复制整套实现。列少量能被证伪的解释，选择能让它们给出不同预测的最小观察。例：显示长度异常可能来自单位换算或读取了旧值；查看同一次操作进入换算前的数值及单位，可以比重复点击更有效地区分两者。每个实验先知道哪种结果会推翻当前解释；未经授权不改配置、插桩或运行。

规则或方案是否必要存在实质争议，且现有证据不足时，可选一次最小对照：保持相同输入、环境和其他条件，只改变一个候选因素，比较预先选定的正确性、错误路径、耗时或用量等可观察结果。只在当前授权的隔离样例或可回退测试环境中执行，不为对照删改真实规则、绕过保护或触碰生产；缺少授权时仅给出观察方案与未执行项。结果相同不等于该因素普遍无用，无法区分时保留 UNKNOWN 并说明样例局限；已有证据足以决定时跳过，不新增固定测试关卡、扩大验证预算或重跑未受影响的已通过检查。

把因果链和修复建议分开。可达路径与确定性语义足以证明源码缺陷时，标明静态确定性证据；运行环境没有复现仍写未运行。只看到相关性时报告首个偏离及下一观察，不把“最可能”包装为已确认根因。多个解释对当前证据预测相同时，继续最窄区分或保留 UNKNOWN，不靠罗列风险凑结论。

给实施方的输入应能落地：精确出错边界、应恢复的不变量、受影响的直接消费者、能暴露原问题的行为检查，以及不能据此改变的边界。无需替开发设计整套新架构或修改工程来证明自己。
