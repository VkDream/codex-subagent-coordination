# 工具结果输出优化：方法与一次实测

更新日期：2026-09-09。

这次更新把两项已在本机采用的做法同步到[全局规则模板](../rules/GLOBAL_AGENTS.md)：实现方案按最小充分路径选择；结构化工具结果先筛选去重，再交给模型阅读。下面的 Token 对照只验证第二项，不能用来证明第一项的收益。

## 具体怎么做

工具结果在执行层处理：相关正文保留一次，并保留来源 URL、文件位置或游标。重复高亮、与正文重复的摘要、无关包装不再重复输出。工具清单先筛名称和描述，再读取选中工具的完整参数。

探索性文本以约 1,000–3,000 tokens 为软目标。信息不够时，按位置或游标补读缺口；不要反复读取已经覆盖的全文。这个数值不是硬截断阈值，也不要求额外安装 tokenizer。

以下内容必须保留：

- 错误原文、失败、UNKNOWN，以及会推翻当前判断的证据。
- 分页、截断和未覆盖范围，避免把部分结果误认为全部结果。
- 合同、源码、补丁、审批边界、接力胶囊，以及用户明确要求完整读取的内容；这些不受上述软目标裁剪。

这些要求已写入全局模板的“MCP 强制路由门”，沿用原有 MCP 优先、授权和失败熔断要求。这里使用原生字段筛选，没有安装压缩代理、常驻包装服务或 Headroom。

## 这次如何验证

使用 2026-09-09 一次 OpenAI Developers Docs 搜索的真实返回：查询为 `Codex token rates`，返回 3 条结果，总匹配数为 30。精简组保留这 3 条结果的完整正文、URL 和分页元数据，去掉重复展示字段。

另外加入明确标注的合成负例，覆盖审批过期、GUI 未授权、UNKNOWN、权限拒绝、分页不完整、源码与精确错误信息。两组分别交给两个独立子任务：使用相同问题、完整读取各自文件一次，回答 12 个核查问题；评分答案未提前提供给它们。作者再对照原文核验答案，并比较受保护字段。

| 指标 | 原始组 | 精简组 |
|---|---:|---:|
| 对照文件字符数 | 28,483 | 13,234 |
| 读取前模型输入 tokens | 41,992 | 41,985 |
| 读取后模型输入 tokens | 50,228 | 45,887 |
| 前后输入增量 tokens | 8,236 | 3,902 |
| 每组两次响应的输入与输出总 tokens | 93,828 | 90,120 |
| 核查答案正确数 | 12/12 | 12/12 |

本例读取后的输入减少 **4,341 tokens，约 8.64%**。数据文本字符数减少约 53.54%；两次响应的输入与输出总量减少约 3.95%。这三个比例口径不同，不能互相替代。

两组结果中的正文、URL、分页信息和受保护字段保持一致。未知问题仍回答 UNKNOWN；准备就绪没有被解释成 GUI 已授权或验证通过；权限拒绝没有被解释成允许重试。

## 如何理解结果

这是一次真实搜索样本加合成负例的对照，不是多工具、多轮随机实验。两组初始输入相差 7 tokens；输出和推理长度会波动，精简组输出反而更多。前后输入增量还包含工具调用等开销，因此不是单个数据字段的精确 Token 计数。

运行记录显示两组使用 `gpt-5.6-luna`、`max`；服务层没有明确记录，保持 UNKNOWN。这是本次运行记录，不代表接收者账号拥有相同模型或未来仍支持这些设置。

[脱敏数据摘要](../evidence/2026-09-09-tool-output-projection.json)保留了计算所需的聚合数值与核查结果。原始私有运行日志未公开，所以读者可以复算这些比例，但无法仅凭本仓库独立复现历史模型计数；相关测试结果属于作者本地验证记录。

本例证明了这次输入下降且 12 项答案保留，不能承诺所有任务或账号额度固定节省 8.64%，也不能换算成账单。全局规则落盘不证明其他已运行任务自动重载，更不证明接收者环境完整运行通过。

## 如何采用

已有这份分享包时，先备份并比较 `rules/GLOBAL_AGENTS.md` 与自己的有效全局指令，按需合并变化，并按[个性化设置说明](../个性化设置.md)处理路径占位符。

保留原有模型和推理要求，先在自己的典型工具结果上做小范围对照：检查关键事实、错误、权限和未知项是否完整，再看实际输入是否下降。只读过本仓库、复制了文件或看到配置存在，都不能直接声称优化已在当前任务生效。
